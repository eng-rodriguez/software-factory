---
name: workspace-context
description: Resolve factory configuration and artifact paths for repository mode or explicitly configured parent workspaces. Use before factory onboarding, orchestration, agents, or artifact writing.
---
Find the nearest ancestor `.factory/workspace.yml` from the session directory or target repository. No manifest, or a target not listed in it: retain existing repository mode, including `.factory.yml`, AGENTS.md/CLAUDE.md and the polyrepo home repository. Do not create workspace mode implicitly.

A workspace manifest has `version: 1`, `mode: workspace`, and `projects` mapping project IDs to `{path: direct-child-directory}`. Each project must be a distinct existing Git root immediately below the workspace, without symlinks. Its external config is `.factory/projects/<id>.yml`; IDs and paths contain only letters, digits, underscores and hyphens. A listed repository with `.factory.yml` is a conflict: stop and report it; never silently override or migrate it. The hook resolver in `hooks/scripts/lib.sh` implements this contract.

In workspace mode:
- Read the parent `.github/copilot-instructions.md` (or parent AGENTS.md/CLAUDE.md), `.factory/projects/<id>.yml`, and optional `.factory/projects/<id>.md`. Existing child instructions are read-only context; report conflicts with the workspace policy.
- Resolve all project commands and area paths relative to that project's Git root. Config uses the existing `default_branch` and `areas` schema, with optional `commands.check` containing the project's existing complete local check command. Treat configured commands as trusted executable configuration. Check commands must not deploy, push, or modify cloud resources.
- Replace AI artifact references to `docs/stories`, `docs/briefs`, `docs/adr`, `docs/closing-notes`, `docs/domain.md` with `<workspace>/.factory/stories`, `briefs`, `adr`, `closing-notes`, `domain.md`. Store written research/review reports under `.factory/reviews`. These explicit workspace paths override agents' default artifact paths and documentation-only write restrictions. Application documentation, API schemas and tests remain in their owning repositories when required by the approved task.
- Never create AI instructions, configuration, skills, planning files or review reports inside child repositories. Never copy central artifacts into them for CI. Never initialize Git at the workspace root or commit central artifacts into an application repository.
- Pass every delegated agent the mode, absolute workspace and target Git roots, external configuration/context paths, and resolved story/brief paths. Each agent loads this skill even when invoked directly. Agents must preserve their role's write restrictions, with only AI artifact paths remapped.
- Run Git, tests, scanners and formatting from the owning repository. Record a baseline commit and check results per changed repository. Local hooks are a safety net, not a sandbox; shell wrappers and client-specific tool payloads require runtime verification.
- Use one branch and PR per changed repository. Determine merge/rollout order from actual dependencies, including GitOps reconciliation. Never merge or deploy. Do not commit central stories, briefs or closing notes at workflow commit steps.
- Scope validation compares each repository's diff with its portion of the external brief. Run this locally and report results; never claim CI read the external brief. Preserve all existing CI controls. If a required CI control needs an in-repo artifact forbidden by workspace policy, stop and report the incompatibility rather than weakening it.
- PRs use the normal format, but omit local-only artifact links. Use a real shared ticket/document URL if available; otherwise say `Brief: local workspace artifact` and summarize relevant decisions and manual verification in Technical Notes. Do not upload central artifacts without authorization.

Workspace onboarding is a separate branch of onboard-project: inspect repositories read-only, draft the manifest, external project configs/context and parent instructions, obtain the skill's draft approval, then write only at the parent. Do not execute repository onboarding steps that create branches, workflows, CODEOWNERS, docs or PRs. Preserve existing parent files by merging narrowly. Do not change an existing repository-mode installation without an explicit migration request.
