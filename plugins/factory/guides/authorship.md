# Author identity and writing voice

Commits, PR titles/descriptions, briefs, ADRs and closing notes represent the user's work. Write in the user's or team's engineering voice, preferably with direct, neutral statements about the change. Do not describe the assistant's process or claim Claude, Codex, Copilot, GitHub, OpenAI or another tool as the author. Mention tools when technically relevant to the implementation; this is not a ban on product names.

- Commit messages are a single Conventional Commit line: `type(scope): imperative summary`, at most 72 characters. No body, tool signature, generated-by footer or `Co-Authored-By` trailer. PR descriptions follow pr-format and have no tool attribution.
- Do not invent personal experience, manual verification, approval or authorship. Attribute verification accurately: automated checks ran; a human confirmed a manual step only if they actually did.
- Before creating a commit, inspect the repository's configured `user.name` and `user.email`, then `git var GIT_AUTHOR_IDENT` and `git var GIT_COMMITTER_IDENT` to catch environment overrides. Both must match the user's established identity for this repository. Do not accept Git's auto-guessed machine identity, a bot/service account, or an assistant identity as a substitute. A user-selected GitHub privacy/noreply address is still the user's identity.
- Reuse identity already explicitly configured/confirmed for the project; do not ask again unnecessarily. If missing or conflicting, finish preparing the changes and message, then ask only for the missing identity before committing. Never infer an email from a username, host name, repository owner or another contributor's commit. Set repository-local configuration only with the user's authorization; never silently change global Git configuration or override author/committer environment variables.
- Before opening a PR, verify the active authenticated GitHub account (`gh api user --jq .login`) matches the user's established account for the target host. The authenticated account determines the PR author; editing the body cannot change it. If authentication is missing or belongs to a bot/other person, keep the PR draft ready and request the appropriate login. Never create a PR under another identity or automatically switch accounts.
- Preserve genuine historical authorship when cherry-picking or applying another contributor's work. Do not rewrite existing commits, signatures or PR authors to conceal their origin; any requested history correction is a separate explicit action.

The distributed Claude settings disable automatic commit/PR attribution. Other clients must honor the same content and identity rules; do not claim settings for one client configure another.
